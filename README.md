# 道体·玄盾 个人版（Personal Edition）

> **版本**：v0.1.26-alpha（独立产品线，内测中）
> **定位**：保护个人用户在使用第三方 AI 中转站时的数据安全与交互安全
> **形态**：桌面应用（Windows）+ 本地 HTTP 代理
> **与 企业版关系**：共享核心检测引擎，产品形态/部署方式/交互界面完全独立

## 本版更新（v0.1.26-alpha）

**为什么建议尽快升级**：这一版修的是「看起来正常、实际没做到」的几处问题，
其中一条会让**日志与界面说谎**——流式回答里高危内容其实已经交给 AI 工具了，
日志却记「已拦截」。

### 修了什么

| 问题 | 之前 | 现在 |
|---|---|---|
| 流式高危内容 | 内容已经发给 AI 工具，日志还写「已拦截 / 危险 +1」 | 内容已送达就如实记「事后告警」；**工具调用帧在验证通过前一律扣住**，不交给客户端执行 |
| 流式结束标记 | 客户端会收到两个 `[DONE]`，且阻断通知排在 `[DONE]` 之后（严格客户端根本读不到） | 只发一个 `[DONE]`，阻断通知一定在它之前 |
| 跳过首启向导后改设置 | 改安全级别 / 端口 / 日志保留**一律 400**，报「中转站地址不能为空」 | 只校验本次提交的那一块，不再连锁封死 |
| 表单填错时的提示 | 只说「HTTP 400 Bad Request」，不知道该改哪一项 | 直接说出是哪一项不对（例如「端口必须是数字」） |
| 切换中转站 | 会把上一家填的 Key 写进这一家，之后这家全 401 且界面无异常 | 切站即清空 Key 草稿与上一家的测试结论 |
| 测试连接中点保存 | 按钮永久停在「测试中…」，只能重开页面 | 锁一定会释放 |
| 异常请求体 | 一次畸形请求可让设置页整页失效，直到重启引擎 | 一律拒绝并保持运行态不变 |

### 顺带修的发布链
- 护栏是否编进安装包的检查，原来的判据**恒真**（用的字符串恰好由个人版自己输出），
  等于一个月来这道门禁没起作用；现在改用护栏专属符号，并加了「护栏缺失必须失败」的负样本。
- 脱敏还原、误报回归、变异检测、护栏一致性等 8 个安全关键测试正式入库，
  测试基座强制隔离你的真实数据目录（不再读写真机配置）。

> v0.1.24 / v0.1.25 的那个「保存必然失败」已在本版之前的 v0.1.25 修掉；
> 本版不含新的破坏性改动，可直接覆盖安装。

### 这四种情况不再打断你

| 你之前看到的提示 | 当时到底发生了什么 | 现在 |
|---|---|---|
| 「响应调用了本轮请求中未声明的工具：`CheckCommandStatus`」 | AI 工具把「跑命令」拆成了执行 / 查状态 / 取输出几个名字，模型这次用了另一个 | 认作同一个能力，只记录，不打断 |
| 「Tool Call 参数包含 Python 内联执行危险操作」 | AI 用 `python -c "…"` 跑一段一次性检查脚本（比如查 git 状态） | 不再拦；只有脚本里真的出现联网、动态执行才拦 |
| 「Tool Call 试图读取环境变量文件：`.env`」 | 命令把 `.env` 当**搜索关键字**用（对仓库做体检），一个字节都没被读出来 | 只记录「提到了」；真去读仍然拦 |
| 「响应中出现未经本代理生成的脱敏占位符」 | AI 正在回答里解释 `⟦XD_n⟧` 这个格式长什么样 | 只有本会话确实做过脱敏时才拦；没有可被替换的原值就只记录 |

### 没有放宽的部分

`rm -rf`、磁盘格式化、反弹 shell、下载并执行远程脚本、
真的去读 `.env` / SSH 私钥、在已脱敏的会话里伪造占位符编号 ——
**仍然按原样阻断**。这一版减少的是误判，不是拦截面。

另外，回答里出现密钥形态时仍然会拦（那是硬证据），
但提示从「输出内容命中高危违规模式」换成能看懂的话，
并直接告诉你要做什么（核对是否真实、真实就换掉）。

### 顺手修好的小毛病

- 日志列表为空时会说明「还没有记录」，不再是一片空白
- 「清空日志」点一次就够，不会因为连点重复提交
- 证据包取不到时会明说「这次没取到」，不再和「这条确实没有痕迹」混为一谈
- 详情抽屉不再闪一下才出内容
- 设置保存失败会写清原因，而不是无声无息
- 更新包下载加了超时，不会永久停在某个百分比

## 一、这是什么

**个人版玄盾是一道部署在用户电脑上的"本地安检站"——在你和 AI 中转站之间，检查每一笔进出的数据。**

用户在使用第三方 AI 中转站（各类 OpenAI/Claude 代理服务）时面临四类风险：

| 风险类型 | 说明 | 后果 |
|---------|------|------|
| 响应注入 | 中转站篡改模型返回，插入恶意工具调用 | 本机执行恶意命令 |
| 凭证窃取 | 中转站扫描流量，窃取 API 密钥/AWS 凭证 | 账号被盗、云资源被滥用 |
| 提示词篡改 | 中转站修改系统提示词，操控模型行为 | 模型输出被操控 |
| 数据截留 | 中转站保留对话记录，倒卖数据 | 隐私泄露 |

### 产品定位：透明防火墙

**玄盾是防火墙，不是安全助手。**

防火墙不询问用户「要不要拦」，它直接拦。用户不需要知道它在工作，
只在危险被挡下的那一刻收到信号。层次结构：

| 层 | 职责 | 打断用户？ |
|---|------|-----------|
| ① 响应侧自动拦截 | 检测到高危内容直接阻断，AI 工具收到错误响应 | 否 |
| ② 请求侧自动脱敏 | 静默替换敏感信息为占位符，返回时本地恢复 | 否 |
| ③ 托盘图标变色 | **实时**状态可见的唯一通道 | 否 |
| ④ 激活状态提示 | 未激活时状态栏显示「只读模式」，不谎报正在防护 | 否 |
| ⑤ 日志事后查阅 | 用户想了解细节时主动打开 | 否 |

**为什么托盘是唯一的实时通道**：用户对中转站返回了什么完全无感 ——
他看到的只是 AI 工具展示的结果。若中转站偷偷插入恶意 tool call、
篡改系统提示词，用户毫无察觉。而玄盾无法控制第三方 AI 工具的 UI，
托盘图标是代理形态下唯一可行的**实时**感知通道
（激活状态、日志属于用户主动查看的**非实时**通道，不在此列）。

**托盘必须常驻**：关闭窗口只是隐藏到托盘，代理继续运行。
若允许关窗口带走进程，用户会在无感知的情况下失去防护 ——
而这正是「透明」最危险的地方：用户看不到的失效，等于没有防护。

## 二、两个版本的区别

玄盾有两条产品线，解决的是**完全相反**的问题。

### 企业版：保护模型

面向自建 AI 网关的团队。模型部署在机房，用户通过企业内部网关访问。
网关是团队自己运营的，因此要防的是**内部或外部流量对模型的攻击**：

- 恶意用户在输入里构造越狱指令、注入系统提示词
- 有人试图套取系统提示词、诱导模型输出违规内容
- 批量异常请求、探测攻击

使用者是运维人员，配置在服务端，实时状态看控制台面板。

> 📘 企业版是**独立产品线**，面向自建 AI 网关的团队，部署在服务端。
> 本仓库只包含个人版，企业版的获取与接入请通过正式渠道咨询。
>
> 如实说明：企业版当前仍有两项能力未实现（管理控制台后端端点、
> 企业 Key 签发验签），评估时请避开误判。

### 个人版：保护你自己

面向使用第三方 AI 中转站的个人用户。模型在别人手里，
中转站也是别人运营。你付钱给他们，把提示词、对话、API 密钥发过去，
风险是**他们一边收钱一边看你的数据，或者在返回内容里动手脚**。

| 维度 | 企业版 | 个人版 |
|------|--------|--------|
| 部署位置 | 机房 / 服务器 | **你的电脑** |
| 谁在运营 | 你的团队 | 第三方中转站 |
| 保护对象 | 模型 | **你** |
| 主要风险 | 越狱、提示词注入 | 中转站偷看数据、返回内容被动手脚 |
| 主要手段 | 输入侧检测拦截 | **输出侧验证 + 本地脱敏** |
| 使用者 | 运维人员 | **普通用户** |
| 感知方式 | 控制台实时面板 | **系统托盘图标** |

两者**共享部分检测组件**，但形态、部署方式和防护目标完全不同。
个人版只复用「输出护栏」这一个组件（提示词注入 + 敏感泄露两类判据），
不加载企业版的输入侧管道、动态壳与内容审核 —— 个人版做的是
**出站脱敏 + 响应验真**，不是内容审查。

本仓库只包含个人版；企业版是另一条独立产品线。

## 三、核心检测流程

```
你的请求 → 玄盾本地代理接收
    ↓
【第一步】请求侧脱敏
    ├─ 扫描 API 密钥、手机号、邮箱、身份证、银行卡
    ├─ 按策略：警告 / 阻断 / 打码
    └─ 打码后转发给中转站
    ↓
中转站转发给模型 → 模型返回
    ↓
【第二步】响应侧完整性验证
    ├─ 危险命令检测（删库 / 反弹 shell / 远程脚本执行）
    ├─ 系统提示词是否被篡改
    ├─ 响应模式异常（长度/结构突变）
    ├─ 敏感信息泄露（回显了你发出去的内容）
    └─ Unicode 隐写载荷（人眼看不见但模型能读）
    ↓
【第三步】本地恢复被脱敏的内容
    └─ 返回给 AI 工具
    ↓
记录到本地日志
```

## 四、核心功能

### 4.1 中转站响应验证（核心）

检测中转站是否篡改了模型返回：

| 检测项 | 说明 | 处置 |
|--------|------|------|
| Tool Call 危险参数 | 返回中的 tool call 是否包含 `rm -rf`、反弹 shell（`nc -e` / `bash -i >& /dev/tcp/…` / `python -c socket`）、`curl \| sh`、访问 `/etc/passwd` | 按安全级别：提示 / 阻断 |
| 系统提示词注入 | 返回内容是否真的**吐出了**系统提示词或内部指令（判断依据是输出护栏的泄露判定，并且正文里能找到泄露陈述；不靠「出现了这几个字」） | 按安全级别：提示 / 阻断 |
| 敏感数据回传 | 回答正文里出现了真实凭证形态的字样（sk- / AKIA / PEM / JWT，带左边界，普通英文复合词不命中） | 按安全级别：提示 / 阻断（文案会提示换密钥） |
| 占位符伪造 | 本会话**确实做过脱敏**，却回传了未登记的 `⟦XD_n⟧`，试图探测原始值 | **阻断**；本会话从未脱敏时（没有可置换的原始值）仅记录 |
| 模型降级 | 同一会话中，中转站实际返回的模型与请求的模型不一致（日期快照后缀如 `-1017` 视为同一模型） | **均衡档起直接阻断** |
| 响应长度突变 | 同一会话中某次返回长度突然偏离历史均值 3σ | 仅记录（不阻断） |
| 响应结构突变 | 返回的 JSON 结构、字段顺序异常 | 仅记录（不阻断） |
| Unicode 隐写载荷 | **人眼渲染为空白、模型却能读出指令**的编码载荷（详见 5.1.1） | 高亮警告 |

> 说明：统计类信号（长度/结构突变）只说明「这一次和平时不一样」，
> 不指向任何安全问题，因此永远**只记录、不阻断**，也不改变托盘颜色。

#### 4.1.1 Unicode 隐写检测（stealth 攻击）

这是 2025–2026 年实证的 stealth 攻击主流。共同点是**人眼审查完全看不出异常**，
但模型 tokenizer 能还原成可执行指令——包括绕过外部安全分类器。

| 手法 | 原理 | 实测绕过率 |
|------|------|-----------|
| **Unicode Tags 块**<br>U+E0000–U+E007F | 每个字符 = `0xE0000` + ASCII 码点，渲染为完全空白。wunderwuzzi 的 *ASCII Smuggler*（2024-01）即此手法；CVE-2025-53773（GitHub Copilot RCE）链路确认可触发 | StegoAttack 论文测得对外部安全分类器绕过率 **>92%** |
| **变体选择符**<br>U+E0100–U+E01EF / VS1-16 | 依附在可见字符后的不可见选择符，可承载隐写 | — |
| **零宽字符二进制隐写** | `U+200B`=0 / `U+200C`=1 / `U+200D`=终止符，可把任意指令编码进一条「空行」 | Knostic 2025-10 实证（GlassWorm 事件 **35,800+** 安装量） |
| **同形异义字** | 西里尔 `а`(U+0430) 冒充拉丁 `a`，肉眼无法区分，直接绕过拉丁字节序列的关键词匹配 | Capital One 2025-08 研究：开源模型 **42.1%–58.7%** |

> 玄盾会在告警中**直接给出解码后的原文**——只报「发现不可见字符」等于让用户
> 仍然不知道敌人到底写了什么。

**误报控制**：Tags 块判据是「连续 4 个以上」（ISO 语言标签的合法用途不会出现连续十几个不可见字符）；
同形异义字判据是「西里尔字母占比 < 25% 却出现同形字」——俄语/乌克兰语正文夹带产品名不会被误伤。

### 4.2 本地敏感信息脱敏

| 类型 | 示例 | 默认策略 |
|------|------|----------|
| API 密钥 | `sk-xxx`、`AKIAxxx` | 阻断 |
| 手机号 | `138xxxx1234` | 打码 |
| 邮箱 | `user@example.com` | 打码 |
| 身份证 | `110101xxxx` | 阻断 |
| 银行卡 | `6222xxxx` | 阻断（默认未勾选，见设置页） |
| 自定义关键词 | 用户手动添加 | 按用户设置 |

**执行方式：自动、静默、无弹窗。** 用户全程无感 ——
脱敏后转发给中转站，响应返回时由第三层本地恢复为原始值，
用户看到的响应与未脱敏时完全一致。日志页可事后查看每处脱敏的类别与位置。

唯一的例外是「阻断」：命中高危类别且安全级别为严格时，请求不会发出，
AI 工具会收到明确的错误提示 —— 这是必要的，因为发出去就等于泄露。

### 4.3 中转站信誉评估

| 维度 | 数据来源 | 说明 |
|------|----------|------|
| 响应延迟模式 | 本地记录 | 条件触发型攻击会在前 N 次调用中表现正常 |
| 数据保留迹象 | 响应内容分析 | 检测响应中是否包含中转站自身的水印 |
| 已知恶意指纹 | 内置信誉库 | **尚未接入真实威胁情报**：库内目前只有两条保留域名的占位条目，对真实中转站不会命中。保留该维度是为了将来接入时不必改结构 |
| 用户社区反馈 | 云端同步 | **不做** —— 与「不依赖云端」的核心承诺冲突 |

### 4.4 激活码（一码一机）

个人版需激活码才能使用防护能力。

**怎么申请**

1. 打开客户端左侧的「激活」页
2. 复制页面上的**机器码**（一串 32 位十六进制字符）
3. 把机器码发给服务方，说明你的购买信息（订单号或邮箱）
4. 收到激活码后粘贴回客户端，点激活

**怎么使用**

激活码是一串以 `XDACT-` 开头的字符，粘贴到「激活」页的输入框即可。
激活后状态栏的只读提示会消失，防护开始生效。

有效期以激活时约定的天数为准（常见为 365 天），到期前会显示剩余天数。

**换机器怎么办**

换了电脑或重装系统后，打开「激活」页点「换机」，会生成一串申请码，
发给服务方，服务方会给你一张绑定新机器的激活码。把新码粘贴回去即可。

**未激活时能用吗**

能。界面、日志、设置全部可用，可以先熟悉操作，
但**不执行脱敏与拦截**，请求直接透传。状态栏会显示
「未激活，当前为只读模式」，不会让你误以为正在防护。

> 这样设计是因为：如果只是码过期或换了机器就把软件锁死，
> 反而会让你彻底用不了。明确告诉你「现在没有防护」比让你误以为
> 一切正常要诚实得多。

**激活码丢了怎么办**

机器码可以随时在「激活」页重新复制，不需要保存什么。
激活码本身如果丢了，联系服务方重新发一张即可。

### 4.5 系统托盘（唯一实时感知通道）

| 能力 | 行为 |
|------|------|
| 常驻 | 关闭窗口 = 隐藏到托盘，代理继续运行；只有托盘菜单「退出玄盾」才真正退出 |
| 变色 | 🟢 防护中 / 🔴 今日已拦截 / ⚪ 暂停或代理未运行 |
| 瞬时脉冲 | 刚拦截时红色闪 6 秒后回落，表达「刚刚挡了一次」 |
| 持续态 | 今日累计统计驱动，表达「今天有 N 次」 |
| 菜单 | 打开主窗口 / 暂停防护 30 分钟 / 恢复防护 / 打开安全日志 / 退出玄盾 |

> **为什么没有黄色「可疑」态**：统计类信号（回答变长/变短、结构变化）
> 只说明这次和平时不一样，不指向安全问题。把它染成黄色，等于把正常的
> 编程对话报成「可疑」—— 用户要么被无谓惊吓，要么学会忽略这个颜色。
> 这类计数只在状态栏右侧以「提示 N 条」出现，不进托盘。

图标在 Rust 侧实时光栅化生成（多边形填充 + 3×3 超采样抗锯齿），
无外部资源文件，任意 DPI 下均清晰。

### 4.6 多中转站与专属入口端口

同时用两家中转站时，两家往往连模型 ID 都一样。多数 AI 工具（尤其是 IDE 插件）
按「服务地址」区分供应商，同一个地址只允许填一条 —— 第二家根本配不进去。

玄盾的做法是给每家中转站一个**专属入口端口**：

| 入口 | 地址示例 | 请求发给谁 |
|------|----------|-----------|
| 主端口 | `http://127.0.0.1:18765/v1` | 按 API Key 识别；识别不到就用「当前使用中」那家 |
| A 家的专属端口 | `http://127.0.0.1:18801/v1` | 固定发给 A 家 |
| B 家的专属端口 | `http://127.0.0.1:18802/v1` | 固定发给 B 家 |

- **地址不同，工具才肯让你并存两条。** 两家模型 ID 相同也不冲突。
- 从专属端口进来的请求**不再看 Key**：即使 IDE 里填的是占位串，
  请求也照样发给你在这个端口上指定的那家 —— 账单归属是确定的。
- 主端口的行为与只配一家时完全一样，老配置不需要改任何东西。
- 端口在设置页随时可以分配、修改、取消，**改完立即生效**，不用重启应用。
- 端口被别的软件占用、与另一家撞车、或直接填了主端口，都会当场拒绝
  并说明原因，不会留下一条「界面显示已配好、实际连不上」的记录。
- 额外端口只开放 `/v1` 对话接口；配置、日志这些管理接口仍然只在主端口上。

> 一个进程监听多个端口，所有入口共用同一份配置、日志和信誉数据 ——
> 多开进程会让同一份本地数据库被两边同时写，日志与统计会互相覆盖。

### 4.7 凭证来源与证据包

日志告诉你「拦到了什么」，但真正要回答的是另一个问题：**这枚 token 是谁放进来的？**

- 是你自己手打的？
- 是你的 AI 工具读文件、请求接口带回来的？
- 还是中转站返回的内容里本来就有的？

前两种和中转站无关；第三种才是可以拿去和对方理论的证据。玄盾按 **SHA-256 指纹**给每枚凭证建一条台账，记录它**第一次出现在哪一侧**：

| 首次出现位置 | 含义 |
|---|---|
| 请求侧 · 用户提问 | 你自己贴进去的 |
| 请求侧 · 工具返回 | 你的 AI 工具读回来的 |
| 响应侧 · 模型回复 | **中转站返回的内容里带来的** |

台账只存指纹、打码片段和长度，**不存凭证原文**。指纹的作用是让同一枚 token 跨轮次、跨日志都能对上，同时对方可以用原文算出同样的哈希来复核。

每条日志的详情页都能「复制证据 / 导出 JSON」，证据包里包含：时间、中转站域名、模型、命中位置、指纹、首次出现方向与时间，以及一句明确的判定。它不含原文 —— 证据本身不该再泄露一次。

> **边界要说清**：模型完全可能在示例代码里自己编一枚 `eyJ...` 开头的假 token。
> 所以玄盾能证明的是「这枚凭证不是你这轮发出去的」，而不是「中转站偷了你的账号」。
> 措辞也据此写成「请核实来源」，不写成指控。

## 五、三种部署模式

### 模式 A：轻量模式（推荐给普通用户，首版实现）

用户安装玄盾桌面应用，玄盾作为**本地 HTTP 代理**运行，用户需要手动将 AI 工具的 API 地址改为 `http://localhost:18765/v1`。

- **优点**：无需安装证书，门槛最低
- **缺点**：只能保护 HTTP 流量，无法保护 HTTPS（但大部分 AI 工具支持自定义 API 地址）
- **适用**：Cursor、VS Code 插件、自建脚本等

### 模式 B：完整模式（推荐给技术用户，未来扩展）

玄盾安装本地 CA 证书，作为**系统级 TLS 代理**运行，自动拦截所有 AI API 流量。

- **优点**：全自动，无需修改任何工具配置
- **缺点**：需要安装根证书，macOS 需要用户手动信任
- **适用**：Claude Desktop、浏览器访问、任何使用系统代理的工具

### 模式 C：插件模式（未来扩展）

为 Claude Desktop、Cursor 等主流 AI 工具开发专用插件。

- **优点**：零配置
- **缺点**：需要逐一适配，开发成本高

> **首版只做模式 A**，技术门槛最低、用户体验最直接、能快速验证核心价值。

## 六、能力边界（请勿过度依赖）

这一节写给**普通用户**。夸大数据盾的能力比承认边界更危险 ——
你会基于错误的安全感做出错误决策。

### 能防住的（前提：已正确配置代理）

| 攻击 | 防护方式 |
|------|----------|
| 中转站在**返回内容里动手脚** | 篡改代码、塞隐藏指令 → 拦截；伪造占位符骗取密钥 → 本会话做过脱敏时才阻断 |
| AI 让中转站**执行危险命令** | 反弹 shell、远程脚本执行、删库 → 高危阻断 |
| 你**误把密钥/身份证/银行卡贴进对话框** | 阻断或打码，绝不外发 |
| **Unicode 隐写载荷** | 人眼看不见的编码指令 → 解码后告警（见 5.1.1） |
| 中转站**偷偷留存数据** | 事后可从信誉分看出（不是实时阻止） |

### 防不住的（务必知情）

| 情况 | 原因 |
|------|------|
| ⚠️ **你没改 AI 工具配置** | 玄盾**完全不生效**。它不是全局代理，必须在 AI 工具里把地址改成 `127.0.0.1:18765`。这是最大的落地门槛 |
| ⚠️ **未激活 / 激活码已过期** | 进入**只读模式**：界面与日志照常可用，但**不执行脱敏与拦截**，请求直接透传。状态栏会显示「未激活，当前为只读模式」 |
| ⚠️ **中转站本来就在看你的数据** | 你的提示词与对话在**发送前**就完整交给了它。玄盾只在传输途中动手脚，人家已经看过了。**这是架构问题，不是实现问题** |
| ⚠️ **HTTPS 内容** | 玄盾是明文 HTTP 代理，走 HTTPS 通道时它是透明的 |
| **上游攻击** | DNS 劫持、证书伪造、中转站服务器被入侵、模型被投毒 —— 都在视野之外 |
| **新型攻击** | 规则是有限的。实测通过说明**已知手法**防住了，不代表「网络攻击防住了」 |

> **一句话**：玄盾能防「传输途中被动手脚」和「你自己手滑」，
> 防不了「中转站本来就在看你」。
>
> 若核心诉求是**聊天隐私**，方向应该换本地模型（Ollama / LM Studio）或直连官方 ——
> 那是唯一的真解。玄盾适合的场景是：图方便用便宜中转站，但怕它乱来、怕 AI 乱执行命令。
> 它是**加分的保险**，不是**基础的保障**。

### 几个设计选择

| 选择 | 原因 |
|------|------|
| 首版只做 HTTP 代理 | 不需要安装证书，门槛最低。多数 AI 工具都支持自定义 API 地址 |
| 不依赖云端 | 所有检测在本地完成。日志也存本地，你的数据不经过我们的服务器 |
| 默认均衡模式 | 不激进拦截，先建立信任，再按需提高安全级别 |
| 自动处理，不弹窗询问 | 防火墙的职责是拦住，不是询问 |
| 托盘必须常驻 | 你对中转站返回了什么完全无感。**关窗口即失去防护**是「透明」最危险的反面 |

## 七、安装与使用

### 下载

从 [Releases](https://github.com/zhibaiYingChuan/XD/releases/latest) 下载对应平台的安装包：

| 平台 | 安装包 |
|------|--------|
| Windows x64 | `xuandun-personal_<版本>_x64-setup.exe` |
| macOS（Apple Silicon） | `xuandun-personal_<版本>_aarch64.dmg` |
| Linux x64 | `xuandun-personal_<版本>_amd64.deb` / `.AppImage` |

每个 Release 附 `checksums-sha256.txt`，可用来核对下载完整性。
当前仍是内测版本：功能与规则会随版本调整，不提供稳定版承诺。

### 使用

1. 安装后首次启动会走引导流程，按提示填入你的 AI 中转站地址与密钥
2. 在客户端「激活」页复制**机器码**，发给服务方获取激活码
3. 把激活码粘贴回客户端完成激活
4. **最后一步最关键**：在你的 AI 工具里把 API 地址改成
   `http://127.0.0.1:18765/v1`（详见第六节）
5. 如果同时用两家中转站：在设置页给其中一家分配一个专属端口（如 18801），
   把 `http://127.0.0.1:18801/v1` 填进第二个工具即可（详见 4.6）

> ⚠️ 不改这一步，玄盾**完全不生效** —— 它是本地代理，不是全局代理。
