# 道体·勘合 个人版

**你和 AI 中转站之间的一道本地安检门。**

你发出去的话，先在你自己的电脑上过一遍；AI 回来的话，再过一遍。
对话、密钥、检测记录都留在你自己的机器上。

> **版本**：v0.2.5（内测中）· Windows / macOS / Linux

---

## 它解决什么问题

很多人用 AI 不是直连模型厂商，而是通过「中转站」。它便宜、模型多，但也带来四个绕不开的风险：

| 风险 | 用大白话说 |
|---|---|
| **偷看** | 你发的每一句话，它都能完整读到 |
| **偷密钥** | 你贴进对话的 API Key、云账号密钥，可能被它拿走 |
| **改回答** | AI 的回答在交给你之前，它可以动手脚 |
| **塞指令** | 它可以在回答里藏一条指令，让你的 AI 工具去执行危险命令 |

勘合不假设中转站一定是坏人，但它假设**链路上可能有人不老实**，于是把检查放在你自己这一侧。

---

## 核心功能

### 1. 发出前打码：密钥不裸奔

你按下发送之前，勘合先检查这段话里有没有不该外发的东西：

- **API Key、AWS 云账号密钥、登录令牌、私钥、身份证号**：直接拦下，这一轮不发出
- **手机号、邮箱**：替换成 `⟦KH_1⟧` 这样的占位符，中转站看不到明文
- **历史轮次或工具返回里带的 token**：打码后照常发出，回来再还原

> 为什么分两种处置：你此刻正在贴密钥，必须让你停下来；但历史里已经存在的 token
> 如果每轮都拦，IDE 会把整段历史重发一遍，对话会彻底卡死。打码同样保证原文不外发。

### 2. 回来时验真：回答有没有被动手脚

AI 的回答回来之后，勘合重点看这些：

- **危险工具调用**：`rm -rf`、反弹 shell、`curl | sh`、读 SSH 私钥
- **未声明的工具**：返回一个你从未允许过的工具调用
- **提示词注入**：回答里夹带「忽略之前所有指令」这类内容
- **敏感数据回传**：回答正文里出现了真实密钥的样子
- **Unicode 隐写**：人眼看不见、模型却能读懂的隐藏指令
- **模型降级**：你以为在跟 A 模型说话，实际回答你的是 B 模型
- **约束违背**：你说了「不要删文件」，它却让你删

处置分三档：高危拦下、中危打码、低危只记一条告警。

### 3. 证据台账：每条告警都能说清来源

每条告警都会记下：这段内容**第一次出现在哪一侧**——是你发出去的，还是中转站返回的。
需要时能导出成证据。

这条记录解决的是：**区分「我的任务本来就需要它」和「链路上有人把它取走了」。**

### 4. 三档强度，自己选

| 档位 | 适合谁 | 特点 |
|---|---|---|
| 宽松 | 内部工具、个人助理 | 尽量不打扰，只拦最确定的 |
| 均衡（默认） | 大多数场景 | 安全和体验取平衡 |
| 严格 | 高安全要求 | 宁可多拦，不可漏放 |

### 5. 本地优先

对话、检测记录、证据都只存本机；机器码只存哈希，仅用于激活校验。
不上传、不用于训练。

## 怎么工作

```
你的请求
   ↓
① 本机打码：敏感信息换成占位符 / 直接拦下
   ↓
② 转发给中转站 → 模型返回
   ↓
③ 本机验真：危险操作、藏起来的指令、换掉的模型
   ↓
④ 还原占位符 → 交给你的 AI 工具
   ↓
⑤ 记录到本地日志
```

全程在你电脑上完成，不经过我们的服务器。

用 920 条合成样本跑真实检测管道（固定随机种子，可复现）：

| 档位 | 请求侧拦截率 | 请求侧误报率 | 响应侧拦截率 | 响应侧误报率 |
|---|---|---|---|---|

| 严格 | **100.0%**（160/160） | **0.3%**（1/300） | **97.5%**（156/160） | **0.0%**（0/300） |

响应侧分类型：

| 类型 | 拦截率 |
|---|---|
| 危险工具调用 / 未声明工具 / Unicode 隐写 / 零宽隐藏 / 模型降级 / 约束违背 | 100% |
| 敏感数据回传 | 95% |
| 提示词注入 | 85% |

> **必须说清楚**：这是模板生成的合成语料，不是真实用户流量；它反映的是规则覆盖度，
> 不等于真实世界的拦截率。复现命令：`python tests/benchmark_personal.py`。
>
> ★ 2026-11-12 修正：此前这一栏写的「响应侧 85%、约束违背 20%」是按**错误口径**
> 测出来的 —— 基准脚本把整段 JSON 当正文送检，而生产路径传的是提取后的正文。
> JSON 里的换行是两个字符（反斜杠 + n），判据的 `\b` 边界因此失配，
> 严重低估了实际能力（约束违背真实值是 4/6 而非 1/6）。
> 现在基准与生产共用同一个正文提取器，并对约束违背做了能力族扩展。

## 安装与使用

### 1. 下载

从 [Releases](https://github.com/zhibaiYingChuan/XD/releases/latest) 下载对应平台的安装包：

| 平台 | 安装包 |
|---|---|
| Windows x64 | `xuandun-personal_<版本>_x64-setup.exe` |
| macOS（Apple Silicon） | `xuandun-personal_<版本>_aarch64.dmg` |
| Linux x64 | `xuandun-personal_<版本>_amd64.deb` / `.AppImage` |

每个 Release 附 `checksums-sha256.txt`，可核对下载完整性。

### 2. 激活

1. 首次启动按引导填入你的 AI 中转站地址与密钥
2. 在客户端「激活」页复制**机器码**
3. 把激活码粘贴回客户端完成激活

### 3. 接入（最关键的一步）

在你的 AI 工具里，把 API 地址改成：

```
http://127.0.0.1:18765/v1
```

> ⚠️ 不改这一步，勘合**完全不生效**——它只管发给它的流量，管不到全局。

多家中转站**同时生效，不需要切换**：

- **转发规则只有一条**：请求带谁的 API Key，就发给谁。
  你在 AI 工具里用 A 家的 Key 就是在用 A 家，用 B 家的 Key 就是在用 B 家。
- **主端口永远可用**：`http://127.0.0.1:18765/v1` 一个地址服务所有家，按 Key 分流。
- **专属端口**（设置页可填，如 `18801`、`18802`）：从哪个端口进来的请求就固定发给
  它绑定的那家，完全不看 Key。适合「工具只允许填一个地址、但你想同时用两家」的场景。
- **「兜底」只是个异常兜底**：只有当请求里的 Key 和所有已配置的都对不上时才用它
  （例如你换了 Key 但还没同步到勘合）。平时它不参与分流。

## 能力边界

**能防住的（前提：已正确接入勘合）**

- 你主动贴进对话的密钥、身份证号、手机号、邮箱被外发
- 中转站在返回里塞进危险操作
- 中转站返回里夹带「忽略之前所有指令」这类内容、人眼看不见的隐藏字符
- 中转站偷偷换模型
- 回答里回显真实密钥的样子

**防不住的（务必知情）**

- 你主动把密钥发给模型、且模型正常复述——这属于你自己的操作
- 纯语义级投毒：代码本身无害、恶意在意图，任何基于文本的检测都无法根除
- 从未见过、且与正常内容极像的新型攻击
- 不经过勘合的流量（没接入 = 没防护）

**几条设计选择**

- 检查「回答长度和平时不一样」这类，只记录、不拦
- 正文里出现危险命令只提醒，真正会被执行的工具调用才拦
- 流式回答已经发出去之后才发现危险时，会中断这条回答并如实记一条「事后告警」
