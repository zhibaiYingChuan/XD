# 道体·玄盾 个人版（Personal Edition）

> **版本**：v0.1.0-alpha（独立产品线）
> **定位**：保护个人用户在使用第三方 AI 中转站时的数据安全与交互安全
> **形态**：桌面应用（Windows/macOS）+ 本地 HTTP 代理
> **与 企业版关系**：共享核心检测引擎，产品形态/部署方式/交互界面完全独立

---

## 一、这是什么

**个人版玄盾是一道部署在用户电脑上的"本地安检站"——在你和 AI 中转站之间，检查每一笔进出的数据。**

用户在使用第三方 AI 中转站（各类 OpenAI/Claude 代理服务）时面临四类风险：

| 风险类型 | 说明 | 后果 |
|---------|------|------|
| 响应注入 | 中转站篡改模型返回，插入恶意工具调用 | 本机执行恶意命令 |
| 凭证窃取 | 中转站扫描流量，窃取 API 密钥/AWS 凭证 | 账号被盗、云资源被滥用 |
| 提示词篡改 | 中转站修改系统提示词，操控模型行为 | 模型输出被操控 |
| 数据截留 | 中转站保留对话记录，倒卖数据 | 隐私泄露 |

### 产品定位：透明防火墙

**玄盾是防火墙，不是安全助手。**

防火墙不询问用户「要不要拦」，它直接拦。用户不需要知道它在工作，
只在危险被挡下的那一刻收到信号。四层结构：

| 层 | 职责 | 打断用户？ |
|---|------|-----------|
| ① 响应侧自动拦截 | 检测到高危内容直接阻断，AI 工具收到错误响应 | 否 |
| ② 请求侧自动脱敏 | 静默替换敏感信息为占位符，返回时本地恢复 | 否 |
| ③ 托盘图标变色 | 状态可见的唯一实时通道 | 否 |
| ④ 日志事后查阅 | 用户想了解细节时主动打开 | 否 |

**为什么托盘是唯一的实时通道**：用户对中转站返回了什么完全无感 ——
他看到的只是 AI 工具展示的结果。若中转站偷偷插入恶意 tool call、
篡改系统提示词，用户毫无察觉。而玄盾无法控制第三方 AI 工具的 UI，
托盘图标是代理形态下唯一可行的感知通道。

**托盘必须常驻**：关闭窗口只是隐藏到托盘，代理继续运行。
若允许关窗口带走进程，用户会在无感知的情况下失去防护 ——
而这正是「透明」最危险的地方：用户看不到的失效，等于没有防护。

## 四、核心检测流程

```
用户请求 → 本地代理拦截
    ↓
【第一层】请求侧脱敏（sanitizer.py）
    ├─ 扫描 API 密钥、手机号、邮箱、身份证、银行卡
    ├─ 根据策略：警告 / 阻断 / 打码
    └─ 打码后转发给中转站
    ↓
转发到中转站 → 中转站转发到模型 → 模型返回
    ↓
【第二层】响应侧完整性验证（verifier.py）
    ├─ Tool Call 危险参数检测（rm -rf / curl 陌生 URL / /etc/passwd）
    ├─ 系统提示词一致性（是否被注入）
    ├─ 响应模式异常（长度/结构突变 3σ）
    └─ 敏感信息泄露（中转站是否返回了不该返回的内容）
    ↓
【第三层】恢复脱敏内容（restorer.py）
    ├─ 将打码占位符恢复为原始值
    └─ 返回给 AI 工具
    ↓
记录到本地日志（storage/db.py）
```

## 五、核心功能

### 5.1 中转站响应验证（核心）

检测中转站是否篡改了模型返回：

| 检测项 | 说明 | 处置 |
|--------|------|------|
| Tool Call 危险参数 | 返回中的 tool call 是否包含 `rm -rf`、反弹 shell（`nc -e` / `bash -i >& /dev/tcp/…` / `python -c socket`）、`curl \| sh`、访问 `/etc/passwd` | 高亮警告 + 默认阻断 |
| 系统提示词注入 | 对比返回中的系统提示词与预期基线 | 警告 |
| 敏感数据回传 | 返回内容中回显了用户发出去的密钥/个人信息 | 警告 |
| 占位符伪造 | 中转站回传本代理从未生成过的 `⟦XD_n⟧`，试图探测原始值 | 警告 |
| 响应长度突变 | 同一会话中某次返回长度突然偏离历史均值 3σ | 标记可疑 |
| 响应结构突变 | 返回的 JSON 结构、字段顺序异常 | 标记可疑 |
| Unicode 隐写载荷 | **人眼渲染为空白、模型却能读出指令**的编码载荷（详见 5.1.1） | 高亮警告 |

#### 5.1.1 Unicode 隐写检测（stealth 攻击）

这是 2025–2026 年实证的 stealth 攻击主流。共同点是**人眼审查完全看不出异常**，
但模型 tokenizer 能还原成可执行指令——包括绕过外部安全分类器。

| 手法 | 原理 | 实测绕过率 |
|------|------|-----------|
| **Unicode Tags 块**<br>U+E0000–U+E007F | 每个字符 = `0xE0000` + ASCII 码点，渲染为完全空白。wunderwuzzi 的 *ASCII Smuggler*（2024-01）即此手法；CVE-2025-53773（GitHub Copilot RCE）链路确认可触发 | StegoAttack 论文测得对外部安全分类器绕过率 **>92%** |
| **变体选择符**<br>U+E0100–U+E01EF / VS1-16 | 依附在可见字符后的不可见选择符，可承载隐写 | — |
| **零宽字符二进制隐写** | `U+200B`=0 / `U+200C`=1 / `U+200D`=终止符，可把任意指令编码进一条「空行」 | Knostic 2025-10 实证（GlassWorm 事件 **35,800+** 安装量） |
| **同形异义字** | 西里尔 `а`(U+0430) 冒充拉丁 `a`，肉眼无法区分，直接绕过拉丁字节序列的关键词匹配 | Capital One 2025-08 研究：开源模型 **42.1%–58.7%** |

> 玄盾会在告警中**直接给出解码后的原文**——只报「发现不可见字符」等于让用户
> 仍然不知道敌人到底写了什么。

**误报控制**：Tags 块判据是「连续 4 个以上」（ISO 语言标签的合法用途不会出现连续十几个不可见字符）；
同形异义字判据是「西里尔字母占比 < 25% 却出现同形字」——俄语/乌克兰语正文夹带产品名不会被误伤。

### 5.2 本地敏感信息脱敏

| 类型 | 示例 | 默认策略 |
|------|------|----------|
| API 密钥 | `sk-xxx`、`AKIAxxx` | 阻断 |
| 手机号 | `138xxxx1234` | 打码 |
| 邮箱 | `user@example.com` | 打码 |
| 身份证 | `110101xxxx` | 阻断 |
| 银行卡 | `6222xxxx` | 阻断（默认未勾选，见设置页） |
| 自定义关键词 | 用户手动添加 | 按用户设置 |

**执行方式：自动、静默、无弹窗。** 用户全程无感 ——
脱敏后转发给中转站，响应返回时由第三层本地恢复为原始值，
用户看到的响应与未脱敏时完全一致。日志页可事后查看每处脱敏的类别与位置。

唯一的例外是「阻断」：命中高危类别且安全级别为严格时，请求不会发出，
AI 工具会收到明确的错误提示 —— 这是必要的，因为发出去就等于泄露。

### 5.3 中转站信誉评估

| 维度 | 数据来源 | 说明 |
|------|----------|------|
| 响应延迟模式 | 本地记录 | 条件触发型攻击会在前 N 次调用中表现正常 |
| 数据保留迹象 | 响应内容分析 | 检测响应中是否包含中转站自身的水印 |
| 已知恶意指纹 | 内置信誉库 | 匹配已知的恶意中转站域名（含高风险 TLD 降分） |
| 用户社区反馈 | 云端同步 | **不做** —— 与「不依赖云端」的核心承诺冲突 |

### 5.4 系统托盘（唯一实时感知通道）

| 能力 | 行为 |
|------|------|
| 常驻 | 关闭窗口 = 隐藏到托盘，代理继续运行；只有托盘菜单「退出玄盾」才真正退出 |
| 变色 | 🟢 防护中 / 🟡 今日有可疑 / 🔴 已拦截 / ⚪ 暂停或代理未运行 |
| 瞬时脉冲 | 刚拦截时红色闪 6 秒后回落，表达「刚刚挡了一次」 |
| 持续态 | 今日累计统计驱动，表达「今天有 N 次」 |
| 菜单 | 打开主窗口 / 暂停防护 30 分钟 / 恢复防护 / 打开安全日志 / 退出玄盾 |

图标在 Rust 侧实时光栅化生成（多边形填充 + 3×3 超采样抗锯齿），
无外部资源文件，任意 DPI 下均清晰。

## 六、三种部署模式

### 模式 A：轻量模式（推荐给普通用户，首版实现）

用户安装玄盾桌面应用，玄盾作为**本地 HTTP 代理**运行，用户需要手动将 AI 工具的 API 地址改为 `http://localhost:18765/v1`。

- **优点**：无需安装证书，门槛最低
- **缺点**：只能保护 HTTP 流量，无法保护 HTTPS（但大部分 AI 工具支持自定义 API 地址）
- **适用**：Cursor、VS Code 插件、自建脚本等

### 模式 B：完整模式（推荐给技术用户，未来扩展）

玄盾安装本地 CA 证书，作为**系统级 TLS 代理**运行，自动拦截所有 AI API 流量。

- **优点**：全自动，无需修改任何工具配置
- **缺点**：需要安装根证书，macOS 需要用户手动信任
- **适用**：Claude Desktop、浏览器访问、任何使用系统代理的工具

### 模式 C：插件模式（未来扩展）

为 Claude Desktop、Cursor 等主流 AI 工具开发专用插件。

- **优点**：零配置
- **缺点**：需要逐一适配，开发成本高

> **首版只做模式 A**，技术门槛最低、用户体验最直接、能快速验证核心价值。

## 七、关键设计决策

1. **不做全量 TLS 代理**：首版只做 HTTP 代理，用户手动配置 API 地址。降低门槛，快速验证。
2. **复用企业版核心引擎**：输出护栏、敏感信息检测、提示词泄露检测直接复用，不重写。
3. **不依赖云端**：所有检测在本地完成，不需要联网。中转站信誉库**纯本地**，社区反馈不做。
4. **日志本地存储**：SQLite 存储，用户完全掌控自己的数据。
5. **默认均衡模式**：不激进拦截，先建立用户信任，再引导用户提高安全级别。
6. **透明防火墙，不做用户决策点**：请求侧自动脱敏、响应侧自动拦截，全程不弹窗、不询问。
7. **系统托盘是唯一的实时感知通道**：用户对中转站返回了什么完全无感，而玄盾无法控制
   第三方 AI 工具的 UI。托盘必须常驻 —— **关窗口即失去防护**是「透明」最危险的反面。
8. **托盘变色分瞬时与持续两段**：瞬时脉冲表达「刚刚挡了一次」，持续态表达「今天累计 N 次」。
   合并会让用户无法分辨，脉冲的警示意义被稀释为常态噪声。

## 七·补、能力边界（请勿过度承诺）

这一节写给**普通用户**，不是给开发者的。夸大事盾的能力比承认边界更危险——
用户会基于错误的安全感做出错误决策。

### 能防住的（前提：已正确配置代理）

| 攻击 | 防护方式 |
|------|----------|
| 中转站在**返回内容里动手脚** | 篡改代码、塞隐藏指令、伪装占位符骗取密钥 → 全部拦截 |
| AI 让中转站**执行危险命令** | 反弹 shell、`curl \| sh`、删库 → 高危阻断 |
| 你**误把密钥/身份证/银行卡贴进对话框** | 阻断或打码，绝不外发 |
| **Unicode 隐写载荷** | 人眼看不见的编码指令 → 解码后告警（见 5.1.1） |
| 中转站**偷偷留存数据** | 事后可从信誉分看出（不是实时阻止） |

### 防不住的（务必知情）

| 情况 | 原因 |
|------|------|
| ⚠️ **用户没改 AI 工具配置** | 玄盾**完全不生效**。它不是全局代理，必须在 AI 工具里把地址改成 `127.0.0.1:18765`。这是最大的落地门槛 |
| ⚠️ **中转站本来就在看你的数据** | 你的提示词与对话在**发送前**就完整交给了它。玄盾只在传输途中动手脚，人家已经看过了。**这是架构问题，不是实现问题** |
| ⚠️ **HTTPS 内容** | 玄盾是明文 HTTP 代理，走 HTTPS 通道时它是透明的 |
| **上游攻击** | DNS 劫持、证书伪造、中转站服务器被入侵、模型被投毒 —— 都在视野之外 |
| **新型攻击** | 规则是有限的。实测通过说明**已知手法**防住了，不代表「网络攻击防住了」 |

> **一句话**：玄盾能防「传输途中被动手脚」和「你自己手滑」，
> 防不了「中转站本来就在看你」。
>
> 若核心诉求是**聊天隐私**，方向应该换本地模型（Ollama / LM Studio）或直连官方 ——
> 那是唯一的真解。玄盾适合的场景是：图方便用便宜中转站，但怕它乱来、怕 AI 乱执行命令。
> 它是**加分的保险**，不是**基础的保障**。

```
    │                          洛书映射器在企业版是性能敏感路径（向量编码 + 映射），
    │                          个人版对延迟更敏感，且误报率上升会直接摧毁产品信任。
    │                          建议 0.1.0 稳定后单独立项。
    │
    ├─ 参考实现 ──────────► src/daoti_xuandun/gateway/proxy.py（SSE 流式透传）
    │
    └─ 全新实现 ──────────► sanitizer.py / verifier.py / restorer.py
                            reputation/tracker.py（信誉评估）
                            storage/db.py（个人版专属 SQLite）
                            proxy/app.py（个人版专属代理入口）
                            src-tauri/src/tray.rs（系统托盘）
```

**复用方式**：`personal/` 通过 `pip install -e ../` 安装企业版 SDK，然后 `import daoti_xuandun` 复用核心引擎。
护栏为**可选依赖**：未安装企业版 SDK 时个人版仍可运行（仅少了护栏层检测）。

### 打包（Phase 8）

```bash
cd personal/desktop
python build_engine.py                 # ① 编译 Python 引擎（Nuitka standalone，~10 min）
                                       #    产物：resources/engine/（45 文件 / 113 MB）
npx tauri build                         # ② 打包 NSIS 安装包（Rust release 首次 ~10 min）
```

**为何用 Nuitka `--standalone` 而非 `--onefile`**：
onefile 会自解压到临时目录，该行为特征被杀毒软件判定为 dropper —— 企业版 v1.3.1 曾因此被火绒误报 `Trojan/Intercept.a`。

**当前产物**（v0.1.0-alpha）：

| 项 | 值 |
|---|---|
| 安装包 | `道体·玄盾 个人版_0.1.0-alpha_x64-setup.exe` |
| 体积 | 36.78 MB（未压缩 resources 156.35 MB） |
| SHA256 | `AB9AB3BFFD48AB889A001363A753D75AD447E3CFCAC6D3ECAF7603FE8FA82AA1` |
| 安装验证 | 静默安装退出码 0，665 文件 / 161.65 MB，engine 663 文件完整落地 |

**代理端口约定**（★ 三方一致性）：

| 环节 | 取值来源 |
|---|---|
| Rust 桌面端 | 进程启动时读 `config.json` 的 `server.port`，存 `OnceLock` 锁定 |
| 引擎实际监听 | 由 Rust 传的 `--port` 决定（`proxy/app.py` 的 `run()` 中 `args.port` 优先于配置） |
| 界面展示 | `get_active_port()` 返回**实际运行**端口，非配置值 |

端口在进程内**不热重读**：用户改端口后配置立即落盘但引擎仍听旧端口，若此时改连新端口将彻底失联（连「改回旧端口」的自救都做不到）。改端口后须重启应用。

实测结论：安装后 CDP 读到的 `get_active_port()` 与引擎 `--port` 一致，均为 18765。Rust 侧解析 `config.json` 的 `server.port` 时**只接受 JSON 数字类型** —— 若写成 `"port": "19999"`（字符串），Python 侧 `ServerConfig(**raw["server"])` 会抛 `TypeError` 并回退整套默认配置（端口 18765），而 Rust 若用字符串扫描提取数字会得到 19999，两侧失联且无从恢复。
