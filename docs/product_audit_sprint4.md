## 1. 产品定位与价值主张

### 1.1 产品定位矩阵

| 维度 | 内容 |
|------|------|
| **产品名** | 道体·玄盾（Daoti XuanDun） |
| **一句话定位** | 活性防护 LLM 防火墙 — 为 AI 应用提供数据驱动的动态安全防护 |
| **核心理论** | 拒绝门理论 + 洛书符号映射器 + 动态阴阳壳（语言无关的 Unicode→64卦原型空间映射） |
| **技术差异化** | (1) 不依赖静态规则/签名 (2) 在线学习持续增强 (3) 域距离+结构异常+4-gram 三重检测 (4) 反逆向保护（Nuitka+anti_debug+编译期 key） |
| **商业模式** | 核心算法双许可证（道体研究许可证 v1.0 + 商业授权），外围代码 Apache 2.0 |
| **目标市场** | B 端企业 AI 应用开发者、运维人员、安全工程师 |

### 1.2 价值主张画布（Value Proposition Canvas）

#### Customer Profile（用户画像）

| 维度 | 内容 |
|------|------|
| **用户任务（Jobs）** | 1. 在 Trae/Cursor/Claude Desktop 等 AI 工具中接入 LLM 时保证输入安全<br>2. 拦截提示注入/越狱/编码混淆攻击<br>3. 满足企业 AI 安全合规审计要求<br>4. 在不修改业务代码的前提下快速接入防护<br>5. 对 LLM 流量进行司法取证级审计 |
| **痛点（Pains）** | 1. 静态规则/签名无法应对新型提示注入攻击<br>2. 现有 WAF/API 网关不懂 LLM 语义<br>3. 攻击样本需要预先收集，冷启动期无防护<br>4. 拦截日志易被篡改，取证难<br>5. 多模型路由（DeepSeek/Claude/GPT）缺乏统一安全层<br>6. 海外闭源工具（Cursor/Claude Desktop）流量加密无法检测 |
| **收益期望（Gains）** | 1. 零配置接入，不修改业务代码<br>2. 在线学习让防御能力随使用持续增强<br>3. 哈希链审计日志支持司法取证<br>4. 三端统一桌面应用（Win/Mac/Linux）<br>5. 多模型路由 + 灰度部署支持企业渐进式迁移<br>6. 紧急逃生通道保证业务连续性 |

#### Product Profile（产品画像）

| 维度 | 内容 |
|------|------|
| **产品服务（Products & Services）** | 1. Python SDK（`pip install daoti-xuandun`）<br>2. Tauri 桌面应用（Win/Mac/Linux 三端）<br>3. Flask 引擎 Sidecar（Nuitka 编译反逆向）<br>4. HTTP/HTTPS 代理（拦截 LLM 流量）<br>5. FastAPI 集成中间件 |
| **痛点缓解（Pain Relievers）** | 1. **观察模式**：冷启动零误报（旁听不拦截）<br>2. **内置 200+ 攻击样本**：系统启动即知"什么是坏"<br>3. **三重检测**：域距离+结构异常+4-gram，覆盖 OWASP LLM Top 10<br>4. **SHA256 哈希链审计**：司法取证级防篡改<br>5. **FALLBACK 降级**：引擎不可达时保护性阻断而非放行<br>6. **HTTPS 隧道审计**：即使无法解密也记录元数据 |
| **收益创造（Gain Creators）** | 1. **活性在线学习**：通过请求自动扩展域知识<br>2. **三级模式**（high_security/balanced/low_false_positive）：场景化适配<br>3. **多模型路由**：6 个 LLM 供应商统一接入<br>4. **灰度部署**：渐进式迁移降低风险<br>5. **快照回滚**：配置变更可原子恢复<br>6. **桌面通知**：拦截/告警实时感知 |

## 11. 产品决策记录（ADR-Product）

### ADR-P001：选择 Tauri 而非 Electron

- **决策**：使用 Tauri 2.x 而非 Electron 构建桌面端
- **原因**：(1) 二进制体积小（18.5MB vs 150MB+）(2) Rust 后端性能优 (3) 安全模型更严格
- **代价**：(1) Tauri 2.x 生态较新 (2) WebView2 依赖 (3) CDP 调试受限
- **状态**：✅ 已落地，Sprint 4 验证通过

### ADR-P002：核心算法闭源（道体研究许可证）

- **决策**：核心算法（reject_gate/luoshu_mapper/dynamic_shell）受道体研究许可证 v1.0 保护
- **原因**：(1) 商业秘密保护 (2) 学术研究需授权 (3) 防止竞品抄袭
- **代价**：(1) 开源社区信任度降低 (2) 学术引用受限 (3) 企业白盒审计需授权
- **状态**：✅ 已落地，双许可证模式

### ADR-P003：活性防护架构（观察→学习→自动切换）

- **决策**：接入后不立即拦截，先旁听学习正常语言模式，积累 1000 样本后自动切换
- **原因**：(1) 零冷启动误报 (2) 零配置接入 (3) 防御能力持续增强
- **代价**：(1) 冷启动期无防护（仅记录模拟拦截） (2) 学习样本质量影响效果
- **状态**：✅ 已落地，README "活性防护"章节

### ADR-P004：紧急逃生通道设计

- **决策**：提供 `set_emergency_bypass(true)` 全局放行所有请求
- **原因**：(1) 误报严重时业务连续性兜底 (2) 运维紧急处置
- **代价**：(1) 逃生期间无任何安全防护 (2) 可能被滥用
- **缓解**：StatusBar 全局红色警告条 + 独立 5s 轮询 + 审计日志
- **状态**：✅ 已落地

### ADR-P005：i18n 词典先建后接入

- **决策**：Sprint 3 建立 i18n 词典，Sprint 5 接入组件
- **原因**：(1) 词典建立工作量小 (2) 接入需修改所有页面 (3) 优先级让位于 P0 修复
- **代价**：(1) 当前仅中文 (2) 海外用户阻塞
- **状态**：⚠️ 半成品，Sprint 5 必须完成
