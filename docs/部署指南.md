# 道体玄盾 部署指南

> **面向对象**：企业 IT 管理员、运维人员
> **适用版本**：v1.3.3-beta
> **最后更新**：2026年8月
>
> **产品形态**：玄盾提供**桌面端**（单机透明防护）与 **Web 管理控制台 + 网关**（企业集中部署，本文档重点）两种部署形态。Python SDK 为底层核心库，供开发者嵌入自研服务。技术原理见[白皮书](白皮书.md)，出厂真实能力见[诚实出厂测试](交付前的诚实出厂测试.md)。

## 一、系统要求

### 桌面端

| 平台 | 最低配置 | 推荐配置 | 备注 |
|------|---------|---------|------|

| Linux | Ubuntu 20.04+ / 4GB RAM | Ubuntu 22.04+ / 8GB RAM | 需 libwebkit2gtk-4.1 |

| 项目 | 要求 |
|------|------|
| Python | 3.11+ |
| 依赖 | FastAPI、uvicorn（自动安装） |
| Node.js（仅构建期） | 20+（用于构建 admin-console 前端） |

## 二、端口约定

玄盾存在两个端口，二者职责不同，**请勿混淆**：

| 端口 | 职责 | 监听主体 | 默认 |
|------|------|---------|------|
| **18765** | 桌面端引擎 / 网关本机默认 | 桌面端引擎 `engine_flask.py`；网关 `gateway/app.py` | 桌面端防护端点 |
| **18766** | Web 管理控制台的网关端口 | 网关（Docker 映射 / admin-console dev 代理 / nginx 反代目标） | 集中部署的网关 |

> 桌面端引擎固定监听 `http://127.0.0.1:18765`。Web 管理端在**开发环境**通过 Vite 代理、在**容器/生产环境**通过 `18766` 访问网关。

## 三、安装步骤

### 3.1 Windows 安装（桌面端）

**标准安装**：
1. 下载 `XuanDun_1.3.3-beta_x64-setup.exe`
2. 双击运行安装程序
3. 按向导选择安装路径
4. 完成安装后从开始菜单启动

**静默安装（企业批量部署）**：
```cmd
XuanDun_1.3.3-beta_x64-setup.exe /S
```

### 3.2 macOS 安装

1. 下载 `XuanDun_1.3.3-beta_aarch64.dmg`
2. 打开 DMG，拖拽到 Applications
3. 首次打开：系统设置 → 隐私与安全性 → 点击"仍要打开"

### 3.3 Linux 安装

**AppImage（便携版）**：
```bash
chmod +x XuanDun_1.3.3-beta_amd64.AppImage
./XuanDun_1.3.3-beta_amd64.AppImage
```

**deb 包**：
```bash
sudo dpkg -i XuanDun_1.3.3-beta_amd64.deb
```

### 3.4 Python SDK 安装

```bash
git clone https://github.com/zhibaiYingChuan/XD.git
cd XD
pip install -e ".[engine]"   # 核心检测引擎（含 flask 依赖）
```

> SDK 从源码安装，构建需要 Rust 工具链（用于编译可选加速扩展）；该扩展不可用时自动回退为纯 Python 检测，不影响主流程。

## 五、Web 管理端 + 网关集中部署

Web 管理控制台（`admin-console`）通过网关（`gateway/app.py`）提供可视化配置、监控与告警，适合企业集中部署。

### 5.1 开发环境（本机）

网关默认监听 `18765`；Web 管理端开发服务器（Vite）将 `/api` 代理到**网关端口**。

```bash
# 1. 启动网关（本机默认端口 18765）
python -m uvicorn gateway.app:app --host 0.0.0.0 --port 18765

# 2. 启动管理端前端（Vite，端口 5173）
cd admin-console && npm install && npm run dev
```

> 若你在其他端口启动网关，需同步修改 `admin-console/vite.config.ts` 中的 proxy 目标端口，否则前端会返回 404。

### 5.2 生产环境（Docker Compose）

```bash
# 一键启动网关 + 管理控制台
docker compose up -d

# 查看日志
docker compose logs -f

# 停止
docker compose down
```

启动后访问：
- 管理控制台：http://localhost:8080
- 网关 API：http://localhost:18766
- 健康检查：http://localhost:18766/health

### 5.3 服务架构

| 服务 | 端口 | 说明 |
|------|------|------|
| xuandun-gateway | 18766 | FastAPI 安全检测网关 |
| xuandun-console | 8080→80 | Nginx 静态管理控制台（API 反向代理到网关） |

### 5.4 手动构建镜像

```bash
# 网关镜像
docker build -t xuandun-gateway:1.3.3-beta .

# 管理控制台镜像（需先 npm run build）
docker build -t xuandun-console:1.3.3-beta -f admin-console/Dockerfile .
```

### 5.5 网关 API Key 认证

Web 网关使用**管理密钥 + 企业 API Key**两级认证，默认安全收紧（fail-closed）：

| 密钥类型 | 来源 | 权限 |
|---------|------|------|
| **管理密钥**（主密钥） | 环境变量 `XUANDUN_ADMIN_KEY`（逗号分隔支持多个） | 全部管理端点（模式切换、审计、企业授权吊销等） |
| **企业 API Key** | 由**玄盾（供应商）离线签发**的 RS256 JWT（`XDKEY-<jwt>`） | 仅业务端点（`/api/v1/protect` 等） |

**商业模式**：玄盾向企业客户收费，按套餐（basic/pro/enterprise）与有效期（`exp`）签发企业 API Key 用于授权接入与计量收费。网关只负责**离线验签与用量计量**，**不提供自建密钥**——企业无法绕过供应商自行签发，从机制上保证收费闭环。

**权限规则**：
- 管理密钥：可访问全部端点（含企业授权吊销、模式切换、审计等）。
- 企业 API Key（JWT）：仅可调用业务检测端点；访问管理端点返回 `401`。
- **管理端点 fail-closed**：未配置任何管理密钥时，管理端点返回 `503` 并提示设置 `XUANDUN_ADMIN_KEY`，不会匿名放开。
- **企业密钥 fail-closed**：未配置验签公钥时，任何企业 API Key 请求返回 `503` 并提示设置公钥，不会匿名放行。

**供应商签发企业 API Key（离线，供玄盾内部使用）**：

```bash
# 1. 生成签名公私钥对（一次即可，私钥保密，公钥分发给网关）
python tools/license_manager/gen_keypair.py --dir /secure/keys

# 2. 签发企业 API Key（按套餐与有效期收费）
python tools/license_manager/sign_api_key.py \
  --key /secure/keys/xuanDun_private.pem \
  --name "某某企业" --tier pro --days 365 --quota 1000000
# 输出 XDKEY-<jwt>，交给企业客户；同时打印 jti（吊销/计量用）

# 3. 供应商自测验签（可选）
python tools/license_manager/verify_api_key.py \
  --public /secure/keys/xuanDun_public.pem --key "XDKEY-..."
```

**网关侧配置公钥**（任选其一）：

```bash
# 方式一：公钥文件路径
XUANDUN_PUBLIC_KEY_PATH="/etc/xuandun/xuanDun_public.pem" \
  python -m uvicorn gateway.app:app --host 0.0.0.0 --port 18765

# 方式二：直接给公钥内容
# XUANDUN_PUBLIC_KEY="-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----"
```

**管理控制台「企业授权」页**：展示公钥是否已配置、以及本网关已产生流量的企业授权的套餐、有效期、用量（按 `jti` 计量，存储于 Redis/内存共享状态）与吊销状态。可对指定 `jti` 执行吊销（立即失效，不可恢复）。

**首次部署（开发环境）**：

```bash
# 设置管理密钥 + 企业密钥公钥后启动网关
XUANDUN_ADMIN_KEY="你的强随机管理密钥" \
XUANDUN_PUBLIC_KEY_PATH="/path/to/xuanDun_public.pem" \
  python -m uvicorn gateway.app:app --host 0.0.0.0 --port 18765
```

管理控制台登录时输入管理密钥。登录后在「企业授权」页查看企业密钥用量并管理吊销。

**Docker 部署**：在 `docker-compose.yml` 的 `xuandun-gateway` 服务中设置 `XUANDUN_ADMIN_KEY` 与 `XUANDUN_PUBLIC_KEY_PATH` 环境变量，挂载公钥文件，并挂载 `xuandun-data` 卷以持久化吊销黑名单（`.revoked_keys.json`）。

> **兼容性**：旧变量 `XUANDUN_API_KEY` 仍被识别为管理密钥；旧版"业务密钥可在控制台自建、未配置即匿名访问"的行为已取消——企业密钥改由供应商离线签发，管理端点 fail-closed。

## 六、企业批量部署（桌面端）

### 6.1 标准化配置

1. 在测试机器上完成安装和配置向导
2. 调整设置后导出配置文件
3. 配置文件位置：
   - Windows: `%APPDATA%\com.daoti.xuandun-desktop\config.json`
   - macOS: `~/Library/Application Support/com.daoti.xuandun-desktop/config.json`
   - Linux: `~/.config/com.daoti.xuandun-desktop/config.json`

### 6.2 批量部署脚本

**Windows（PowerShell）**：
```powershell
$computers = @("PC01", "PC02", "PC03")
foreach ($pc in $computers) {
    Copy-Item "\\fileserver\share\XuanDun_1.3.3-beta_x64-setup.exe" "\\$pc\c$\temp\"
    Invoke-Command -ComputerName $pc -ScriptBlock {
        Start-Process "C:\temp\XuanDun_1.3.3-beta_x64-setup.exe" -ArgumentList "/S" -Wait
        Copy-Item "\\fileserver\share\config.json" "$env:APPDATA\com.daoti.xuandun-desktop\"
    }
}
```

**Linux（Bash）**：
```bash
#!/bin/bash
HOSTS=("server01" "server02" "server03")
for host in "${HOSTS[@]}"; do
    scp XuanDun_1.3.3-beta_amd64.deb $host:/tmp/
    ssh $host "sudo dpkg -i /tmp/XuanDun_1.3.3-beta_amd64.deb"
    scp config.json $host:~/.config/com.daoti.xuandun-desktop/
done
```

### 6.3 部署后验证

每台机器运行验证脚本：
```bash
python scripts/verify_installation.py --port 18765
```

## 七、常见问题排查

### Q1: 安装后应用无法启动

- **Windows**：检查 .NET Framework ≥ 4.7.2，以管理员身份运行
- **macOS**：`xattr -cr /Applications/道体玄盾.app`
- **Linux**：`sudo apt install libwebkit2gtk-4.1 libgtk-3-0`

### Q2: 引擎未启动（端口 18765 不可达）

```bash
# 检查引擎进程
tasklist | findstr xuandun-engine    # Windows
ps aux | grep xuandun-engine         # Linux/macOS
```

引擎进程不存在时，重启桌面端应用。

### Q3: Web 管理端灰度比例加载失败（404）

通常是 Vite 代理目标端口与网关实际端口不一致导致。确认 `admin-console/vite.config.ts` 的 proxy 目标端口等于网关监听端口；若网关尚未启动，先启动网关再刷新页面。

### Q4: 观察模式长时间不切换

- 默认需要 1000 条样本（可配置）
- 可在设置中调低阈值
- 或手动切换：设置页 → 切换到保护模式

### Q5: 防护测试失败

- 确认当前为"保护模式"（观察模式不拦截）
- 检查引擎是否运行正常

## 八、升级与卸载

### 升级

- **桌面端**：新版本覆盖安装，配置和数据自动保留
- **SDK**：`cd XD && git pull && pip install -e ".[engine]"`
- **Web 管理端**：重新 `docker compose up -d --build` 或重新构建镜像

### 卸载

- **Windows**：控制面板 → 程序和功能 → 卸载
- **macOS**：删除 Applications 中的应用

### 配置回滚

每次配置变更自动创建快照。回滚：设置页 → 配置历史 → 选择版本 → 回滚。

## 九、管理接口

### 无限消耗防护管理接口

**端点**：`POST /rate/limit`（别名：`POST /api/rate/limit`）

**请求体（JSON）**：

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| action | string | 否 | "all" | status / update_config / reset_session |
| policy | string | 否 | 全部 | 目标安全策略（STANDARD/STRICT/BASIC） |
| session_id | string | 否 | - | 查询指定会话配额 |
| update_config | dict | 否 | - | 更新配置字段 |
| reset_session | string | 否 | - | 重置指定会话配额 |

**配置更新白名单字段**：
- global_qps_limit（全局 QPS，0=不限）
- max_request_length（单请求字符上限，0=不限，默认 8000）
- session_quota_per_minute（会话分钟配额，0=不限，默认 60）
- session_quota_per_hour（会话小时配额，0=不限，默认 1000）

## 十、日志管理

### 10.1 日志轮转

网关启动时自动创建日志文件，10MB 自动轮转，保留 3 个历史文件。

```bash
# 生产环境推荐：通过环境变量指定持久化目录
export XUANDUN_LOG_DIR="/var/log/xuandun"
```

**Docker 部署示例**：
```dockerfile
ENV XUANDUN_LOG_DIR=/var/log/xuandun
VOLUME ["/var/log/xuandun"]
```

> 未设置 `XUANDUN_LOG_DIR` 时使用相对路径 `../logs/`。生产环境必须显式设置，避免日志丢失。

### 10.2 日志格式

所有日志为 JSON 格式，每行一条，可直接接入 ELK/Loki：

```json
{"timestamp": "2026-08-08T10:30:00", "level": "INFO", "logger": "xuandun",
 "message": "检测请求", "event": "protect_request", "session_id": "abc123",
 "allowed": true, "latency_ms": 1.23}
```

### 10.3 审计日志

审计日志与运行日志共用同一文件，通过 `event` 字段区分：
- `protect_request` — 每次安全检测
- `gateway_startup` / `gateway_shutdown` — 服务生命周期
- `engine_ready` / `engine_error` — 引擎状态变更
- `log_setup` — 日志轮转就绪
