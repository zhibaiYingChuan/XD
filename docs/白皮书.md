## 摘要

传统 LLM 安全防御高度依赖攻击样本库——收集已知的提示注入、越狱、编码攻击等模式，构建黑名单或训练分类器。攻击技术快速迭代，基于攻击样本的防御往往滞后。

道体·玄盾采用**异常检测**路线：以正常业务交互为主要学习素材，建立"正常域"的高维表征，对**偏离该域的行为**进行异常判定，并辅以**内置攻击样本**提供初始攻击认知。本白皮书阐述其整体架构、检测维度与活性自适应机制，说明它在"无需事前收集大量攻击样本"前提下进行防护的原理，同时如实说明其能力边界。

> **核心结论**：玄盾不依赖"收集足够多攻击样本"来生效，而是通过"建立正常域 + 检测偏离 + 内置攻击认知"三者结合实现防护。它是活性防护，防御能力随部署环境学习逐步提升，而非静态黑名单。

## 问题背景

当前主流的 LLM 安全防御方案：

| 方案类型 | 工作原理 | 核心局限 |
|---------|----------|----------|
| 关键词黑名单 | 匹配预设敏感词/短语 | 易被变体绕过 |
| 对抗训练/微调 | 用攻击样本微调模型 | 依赖已知攻击库，对未知变体泛化有限 |
| LLM 裁判 | 用另一个 LLM 判断输入是否恶意 | 成本高、延迟大、可能被二次注入 |

这些方案的共同点是：需要一定量的已知攻击样本。攻击从出现到被收录之间存在时间窗口，且攻击者可不断制造变体。

玄盾的切入角度不同：**同时问"这是否偏离正常"和"这是否命中已知攻击特征"**，以前者为核心、后者为加速补充，从而降低对攻击样本规模的依赖。

## 设计理念：检测"正常"而非"攻击"

设系统已学习到正常业务输入的分布 \( P_{normal}(x) \)。对新的输入 \( x_{new} \)，计算其与正常域的偏离程度：

\[
\text{anomaly\_score} = d(x_{new}, D_{normal})
\]

其中 \( D_{normal} \) 是正常域的紧凑表征（原型向量集合），\( d \) 是距离度量。当偏离程度超过阈值时，判定为异常（潜在攻击）。

该范式在网络安全领域已被验证（如流量异常检测）。它在 AI 安全领域的落地受两个技术瓶颈制约：

- **表征**：如何将任意自然语言/字节输入映射到可度量的数学空间？
- **动态演化**：正常业务模式随时间变化，正常域需持续更新。

玄盾通过**正常域映射器**与**活性学习**解决这两个问题。

> 需要说明：仅靠"正常域偏离"并不能覆盖所有攻击类型（尤其与正常文本在统计上高度重叠的攻击）。因此玄盾还内置攻击样本库与多模态检测作为补充，共同构成综合判定。

## 整体架构

```
输入（任意语言/格式）
    |
[快速初筛] —— 命中强攻击信号立即拒绝；明显正常直接放行；不确定进入精判
    |
[深度精判] —— 正常域表征 + 多模态异常检测
    |
[决策引擎] —— 允许 / 拒绝 / 降级（引擎不可达时安全降级）
    |
[响应]   —— 通知 + 日志 + 审计记录
```

核心模块：

- **两级检测**：`outer_gate.py`（快速初筛）+ `inner_gate.py`（深度精判），协同配合、双向反馈。
- **正常域映射器**：`luoshu_mapper.py`，将输入映射到统一的数学表征空间，用于距离比较。
- **多模态判定**：`reject_gate.py`，融合多维度信号综合决策。
- **会话时序校验**：`timing_checker.py`，检测多轮对话中的重复/模式化攻击。
- **预处理**：`preprocessors.py`，增强对编码与混淆攻击的检测。
- **输出护栏**：引擎 `engine_flask.py` 中 `/output/*` 系列端点。
- **告警与审计**：`integrations/notifiers.py`、`alert_manager.py`。

> 各核心算法的具体实现（映射方式、维度、阈值、融合权重、学习参数）受商业机密保护，不在本文档公开。

## 两级检测

为兼顾延迟与准确率，玄盾采用两级结构：

- **快速初筛（毫秒级）**：对强攻击特征做快速判定，命中即拒绝；对明显正常的输入直接放行；仅对"不确定"的输入进入深度精判，以控制平均延迟。
- **深度精判**：对不确定输入做更充分的表征与多模态分析，得到最终结论。

两门之间通过反馈机制持续协同：精判结果用于优化快速初筛的判定，快速初筛发现的边界情况也会反馈回精判。

## 正常域表征与异常检测

系统维护正常域表征（由聚类原型构成，每个原型代表一类常见模式），并内置攻击样本认知。对每个输入：

1. 将其映射为统一空间中的向量。
2. 计算其与正常域原型的距离，评估偏离程度。
3. 同时评估是否命中内置攻击特征。

**活性学习**：被判定为正常的输入会缓慢扩展正常域表征；系统从运行中持续学习，无需人工标注攻击样本。

**冷启动策略**：出厂内置通用良性原型（不包含业务敏感信息，仅提供通用"正常文本"分布参考），确保首日即有基础防御能力；并配合观察模式（见下节）避免冷启动期的高误报。

**抗毒化**：为防止攻击者通过大量无害样本逐步污染正常域表征，系统内置多重防护闸门，包括对更新频率的限制与对总更新次数的绝对上限，达到上限后停止在线学习、冻结表征。具体阈值不公开。

## 多模态异常检测

仅靠"正常域偏离"不足以覆盖所有攻击类型（尤其短文本与语义高度重叠的样本）。玄盾融合多个维度的异常信号形成综合判决：

- **结构维度**：捕获命令式语法、非常规排版、异常标点密度等与正常业务不一致的结构。相关模式从数据中统计学习，而非纯硬编码黑名单。
- **字节维度**：检测编码攻击（Base64/Hex）、混淆攻击（leet speak、同形符）、控制字符注入等。通过字节熵、重复模式、编码特征等统计量识别。
- **时序维度**：捕获多轮对话中的重复攻击模式、低频试探、渐进式越狱。仅在会话有足够历史时启用。

三个维度的得分按安全模式配置的权重融合，形成最终异常得分，与判定阈值比较得到结论。权重与阈值均为可配置项，具体数值不公开。

**预处理管道**（默认开启，可关闭）：Base64/Hex 解码、Unicode 正规化、技术短语白名单，用于增强对编码混淆攻击的检测、降低技术性良性文本的误报。

## 活性学习与观察/保护模式

> 玄盾是会进化的 AI 安全网关：出厂对全新攻击拦截率偏低是进化的起点，能力随部署学习逐步提升。实测同一批全新攻击，出厂保护模式拦截 48.3%，学习进化后达 90.0%。机制与真实数据详见[学习进化报告](学习进化报告.md)。

传统安全产品部署后即进入拦截模式，但系统对新环境一无所知时开启拦截必然产生大量误报。玄盾采用两阶段策略：

```
+----------------------------------+
| 第一阶段：观察模式（LEARNING）    |
|  · 放行所有请求，不拦截           |
|  · 从正常流量学习"正常域"        |
|  · 记录"若开启保护会拦截什么"     |
+----------------------------------+
       | （积累 >= N 条正常样本，默认 N=1000）
+----------------------------------+
| 第二阶段：保护模式（PROTECTING）  |
|  · 正常请求通过，异常请求拦截     |
|  · 持续在线学习，能力持续增强      |
+----------------------------------+
```

- **观察模式**：执行完整检测但**不实际拦截**，业务零影响，同时让运维预览"若开启保护会拦截什么"。
- **自动切换**：积累 ≥1000 条（可配置）正常样本后自动切换；也支持手动提前切换或回退。
- **内置攻击样本库**：出厂内置攻击与良性样本，系统启动即具备基础攻击认知，不依赖观察期积累。

## 输出护栏

输出护栏在**模型输出侧**检测违规内容，与输入侧形成双向闭环——即使攻击者绕过输入检测，模型输出的违规内容仍会被处置。

```
用户输入 -> 输入检测 -> 大模型 -> 输出检测 -> 返回用户
```

输出护栏采用**三级处置**策略：

| 风险等级 | 处置动作 | 说明 |
|---------|---------|------|
| 高 | 拦截（block） | 命中高危违规，直接拦截 |
| 中 | 打码（redact） | 命中敏感模式，对敏感片段脱敏 |
| 低 | 告警（alert） | 疑似违规，放行但记录告警 |

> 输出护栏遵循"绝不断服务"原则：检测过程发生异常时降级放行并告警，不阻断正常业务流程。

## 产品形态与桌面端

玄盾提供三种交付形态，共享同一套核心检测引擎，面向不同场景：

| 形态 | 定位 | 适用对象 |
|------|------|---------|
| **桌面端**（主产品） | 单机透明防护：把模型 `base_url` 指向本地引擎，为本地/远程模型做全链路防护 | 个人开发者、本地 AI 工具使用者 |
| **Web 管理控制台 + 网关** | 企业集中部署：可视化配置、监控、告警，网关为 OpenAI 兼容反向代理 | 企业 IT / 运维 |
| **Python SDK** | 开发者嵌入库：把检测能力直接集成进自研 Python 服务 | 后端开发者 |

> **说明**：Python SDK（`daoti_xuandun`）不是独立的"模式"，而是桌面端与网关底层的**核心检测库**，也可被开发者单独 import。日常使用**无需**直接使用 SDK。

### 桌面端

玄盾桌面端（Tauri + Nuitka 引擎）将防护引擎带到桌面，为运行 AI Agent / 模型的电脑提供守护。

> **重要**：安装桌面端**不会自动拦截**电脑上任何 AI Agent 或模型的流量。桌面端提供需要主动接入的防护方式：

| 方式 | 说明 |
|------|------|
| **① 内置 OpenAI 兼容端点** | 把模型 `base_url` 指向 `http://localhost:18765/v1`，透明做"输入防护 → 转发上游 → 输出防护" |
| **② 手动检测 + 本地 API** | 桌面端「安全检测」页手动检测；或调用 `18765/protect`（输入）/ `/output/protect`（输出） |
| **③ Web 管理控制台（网关）** | 企业集中部署，可视化配置、监控、告警 |

**核心能力**：OpenAI 兼容防护端点、本地 HTTP API、手动检测、MCP Server（`xuandun_protect` / `xuandun_status`）、输出护栏观测与配置、系统托盘驻留、拦截通知、审计日志（哈希链校验）、引擎密钥保护、反逆向工程（Nuitka 编译 + 符号剥离 + 字符串加密 + 反调试检测 + 完整性校验）。

> 桌面端**不包含**自动流量代理/进程嗅探能力。让模型被玄盾保护的最便捷方式是使用内置 OpenAI 兼容端点（改 `base_url`）。

## 运维能力

- **灰度部署**：按比例拦截请求，支持在生产环境小范围验证后逐步放大。
- **逃生通道（紧急放行）**：紧急情况下静默放行所有流量，仅记录 bypass 日志。
- **配置快照与回滚**：重大变更前自动创建快照，支持一键恢复历史配置。
- **日志与审计**：JSON 结构化日志，审计日志含哈希链校验，可追溯、可导出。
- **告警通知**：支持钉钉、飞书、邮件、Webhook、Syslog 等通道，含去重与分级过滤。
- **反馈闭环**：误报可在管理界面标记为"安全"并学习；漏报样本可回灌学习增强。
- **监控指标**：`/status`、`/metrics`、`/api/v1/stats` 等端点输出运行状态、拦截率、延迟、原型统计等。

## 性能与基准测试

> **诚实声明**：玄盾有两份**性质不同**的测试报告，请勿混为一谈：
> - **[交付前的诚实出厂测试](交付前的诚实出厂测试.md)**：用**与出厂预热库零重叠的全新攻击**测产品对"从未见过攻击"的真实拦截能力，反映**出厂真实状态**。

> 以下数据均**不代表对未知或新型攻击的绝对防御**。

### 诚实出厂测试（全新攻击，出厂真实状态）

> 全新攻击样本 60 条（12 大类，与预热库零重叠）、全新良性样本 2311 条，测真实能力而非"背答案"。

| 交付形态 | 攻击拦截率 | 良性误报率 | 双层综合拦截（含输出围栏） |
|---------|-----------|-----------|--------------------------|
| **出厂观察态**（默认） | 15.0% | 0.04% | 35.0% |
| **保护模式**（灰度 100%） | 48.3% | 4.85% | 66.7% |

> 出厂观察态以"不打扰用户"为最高优先级，仅对预热攻击强制拦截，故误报率极低（0.04%），但全新攻击拦截率偏低（15%）。保护模式下拦截率提升，但误报率随之上升——这是拦截率与误报率的固有权衡。完整明细见[诚实出厂测试](交付前的诚实出厂测试.md)。

### 行业基准测试（已知测试集，balanced 模式）

| 基准套件 | 攻击拒绝率 | 良性接纳率 | 攻击/良性样本 |
|---------|-----------|-----------|------------|
| internal_extended（中文扩展） | 90.2% | 92.7% | 204 / 136 |
| owasp_llm_top10 | 78.5% | 88.9% | 195 / 90 |
| raucle_bench_compat | 96.3% | 89.1% | 108 / 55 |

> **两者的关系**：行业基准反映对**已知攻击模式**的覆盖（这些套件在开发期被用于迭代调优，存在"背答案"成分，数据偏高）；诚实出厂测试反映对**全新攻击**的真实拦截能力（明显更低）。**出厂观察态 15% 才是用户首次使用时的真实状态**，行业基准数据不代表对未知攻击的防御能力。

## 已知局限与诚实说明

1. **出厂对全新攻击的真实拦截偏低**：诚实出厂测试显示，出厂观察态对与预热库零重叠的全新攻击仅拦 15%（保护模式 48.3%）。出厂状态以低误报保体验为先，对全新攻击的识别有明显空间，需靠活性学习逐步提升。
2. **测试集熟悉度**：行业基准套件在开发期间用于迭代调优，数据反映对已知模式的覆盖，对未见过的新型变体会明显下降（两者差距见上节）。
3. **良性接纳率受预热语言影响**：默认中文预热对英文测试集友好度有限，需业务语言匹配的预热样本。
4. **符号级检测的理论边界**：当良性与攻击样本在字节分布上高度重叠时，判别存在边界，需结合其他维度与人工复核。
5. **活性防护的进化特性**：初始部署对未知攻击的检测能力弱于成熟期。
6. **不在覆盖范围内的威胁**：语义级高级社工、全新编码方案、多模态攻击、侧信道攻击等，建议结合纵深防御。

## 常见技术质疑与回应（FAQ）

**Q1：业务包含高熵数据（如用户粘贴代码），字节异常检测会误报吗？**

会，但系统内置代码模式识别预处理，可识别 Markdown 代码块、缩进、括号配对等结构化内容；也可将代码类输入加入 `warmup_safe` 或标记为"安全"，系统会自动学习该模式。

**Q2：无需收集大量攻击样本，如何保证对零日攻击的防御？**

玄盾以"正常域偏离"为核心，不依赖攻击样本规模来生效；同时内置攻击样本库提供已知攻击的快速识别。对从未见过且与正常文本统计上高度重叠的攻击可能漏过，此类攻击在多次出现后可被活性学习捕获。**无法给出绝对防御下界。**

**Q3：原型库会无限增长吗？**

不会。系统内置原型合并与遗忘机制控制容量，并设有更新次数绝对上限（抗毒化），保证内存可控、表征不被污染。

**Q4：基准成绩是否意味着无漏洞？**

不是。数据仅反映对内部测试集的覆盖，测试集在开发期被用于调优，真实对抗环境表现会低于报告数据。建议用独立第三方测试集或红队对抗评估获取客观实战数据。

**Q5：核心算法为什么不在白皮书中公开？**

核心算法的具体实现（映射方式、维度、阈值、融合权重、学习参数）属于商业机密，受[道体研究许可证 v1.0](../LICENSE)保护。如需更详细技术文档，请在签署 NDA 后联系技术团队。
